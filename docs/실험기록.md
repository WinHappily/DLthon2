# 실험 기록 — 허RAG해줘 DLthon2

## 1. 평가 세트와 지표

| 세트 | 문항 | 용도 |
| --- | --- | --- |
| 개발 | 150 | 팀 제작. 모델·설정 선택은 여기서만 |
| 잡음 | 90 | 같은 뜻, 오타·말투만 바꾼 변형 |
| 형식 | 30 | 선택형·단답 등 답 형식 변형 |
| 공개 | 100 | 운영진 문항. 판본 규칙을 다듬을 때 일부를 봐서 **오염 있음** |
| 봉인 | 50 | 팀장만 보관. 최종 조합을 기록한 뒤 **한 번만** 실행 |

- 주지표: 판정 상태(가능 / 사전 합의 필요 / 공동 처리 불가 / 추가 확인 / 규정에 없음)와 적용 판본(V1·V2·V3·미정·해당 없음)이 **둘 다** 맞은 문항 수
- 근거 인용 정확도: 근거 채점 대상 문항 중 판정을 가르는 조항·표를 빠짐없이 인용한 비율
- 경량화 효과: 파일 크기와 가중치 메모리(vLLM이 모든 모델에 GPU 90%를 미리 잡아 최대 메모리는 같음)
- 응답 시간: 요청부터 답변 완료까지, 8개 동시 처리 중 측정(혼자 쓸 때보다 길게 나옴)

## 8. 증류

- 학습 질문 860(대조 문항 60 포함), 평가 세트와 겹침 검사(`distill/겹침검사_결과*.csv`)
- 교사 gemma4-31b가 V2·V3 문서로 각각 답(860 × 2). V3 답을 정답과 대조해 맞은 746개만 학습(`distill/C가_고른_문항_V3.txt`)
- LoRA 랭크 16 · 2에폭 · 최대 16,384토큰(8,192이면 9문항만 남아 수정) · A40 2시간 45분
- 교사와 학생의 어휘가 달라 로짓 증류 대신 시퀀스 증류

## 9. 실패와 다음 과제

1. 판본 규칙 과적합: 처음 보는 표현 6건, 날짜 해석 6건 → 개정 항목 판별을 임베딩·LLM으로, 날짜 해석 코드 수정
2. 계산-결론 모순(D109): 계산은 맞고 표의 예시 금액을 상한으로 오해 → 금액 비교를 코드로
3. 증류 일반화 부족 → 잡음·형식 변형을 섞어 다시 증류, 4B 증류본 4비트 양자화
4. 31B에는 판본을 강제하지 않고 힌트로 주는 방식 재검증

## 10. 공정성 절차

- 봉인 50은 팀장 C만 보관, A·B는 열람하지 않음
- 공개 100 · 봉인 50 실행 전에 최종 조합을 팀 노션에 기록, 결과를 보고 모델·규칙·정답을 고치지 않음
- 첫 봉인 실행 뒤 31B 후보 누락을 발견 → "정확도 구성은 개발 세트 점수로만 고른다"를 먼저 기록하고 추가(발표에서 공개)
