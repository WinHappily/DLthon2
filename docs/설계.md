# 설계 — 코드와 모델의 역할 나누기

## 과제가 어려운 이유

운영진 예시 질문 "어머님 생신 식사와 선물을 서로 다른 카드로 결제했어. 공동비로 처리할 수 있을까?" 하나에도 세 가지가 함께 걸린다.

1. **여러 조항과 표를 엮어야 한다** — 행사 한도(표 41), 다른 카드도 한 건으로 합산(제23조), 사전 합의(제79조)
2. **같은 질문도 날짜에 따라 수치가 다르다** — 생신 상한 V1 25만 원 → V2 22만 원 → V3 26만 원(2026-12-01 시행)
3. **결론을 바꿀 정보가 빠지면 되물어야 한다** — 날짜나 사전 합의 여부가 없으면 추측하지 않고 '추가 확인'

규약집 V2는 '제1차 개정 합본'이라 V1 수치(부칙·대조표)와 V2 수치(본문)가 한 문서에 함께 있다. 그래서 판본별로 문서를 나눠 검색하는 방식은 쓸 수 없고, **사건의 기준일로 적용 판본을 고르는 단계**가 따로 필요하다.

## 파이프라인

```
질문
 │
 ├─[코드] 검색 ─ bge-m3 + 재순위, 조각 안의 '제N조 · 표 NN'을 한 단계 따라가 함께 가져옴
 ├─[코드] 판정 메모 ─ 질문 속 금액 합계, 관련 표의 행, 판본 정보를 정리해 함께 넣음
 ├─[코드] 판본 결정 ─ 개정 항목 파악 → 표 07의 기준일 종류 → 날짜 추출 → 부칙 제1조 시행 구간과 비교
 │                    출력 스키마의 '적용_판본' 칸을 그 값 하나로 고정
 ├─[모델] 판정 ─ JSON 스키마 강제: 개정 항목 · 기준일 · 적용 판본 · 조건 · 근거(출처·행·쪽) · 상태 · 답 · 다음 행동 · 확인 질문
 └─[코드] 후처리 R3 ─ '추가 확인'인데 빠진 정보가 합의 여부뿐이고 아직 하지 않은 일이면 → '사전 합의 필요'
```

## 경계를 정한 기준

| 코드가 맡는 것 | 모델이 맡는 것 |
| --- | --- |
| 답이 하나로 정해지는데 틀리면 판정이 통째로 뒤집히는 일: 날짜 → 판본, 금액 합산·비교, 출력 형식 | 어떤 조항이 해당하는지 해석, 상태 판정, 근거 선택, 설명과 다음 행동 |

이 경계를 넘어 판정 자체를 규칙 사전으로 내리는 것은 일부러 보류했다.

1. 운영진 핵심 질문은 "모델을 줄여도 판단할 수 있나"다. 코드가 판정하면 모든 모델이 같은 점수가 되어 모델 비교가 의미를 잃는다.
2. 규칙은 개발 문항의 오답을 보고 만들게 되어 과적합된다. 실제로 판본 규칙은 개발 150에서 100%, 봉인 50에서 82% / 74%였다.
3. 규약이 개정될 때마다 규칙을 다시 고쳐야 한다.

## 판본 규칙의 변화 (A)

| 판 | 내용 | 정확도 |
| --- | --- | --- |
| g1 | 표 07 개정 항목 + 기준일 + 시행 구간 | 개발 50 중 43 |
| g2 | 틀린 문항마다 단어를 넣지 않고 원리로 수정(가족행사 범위, 비용·술자리 구분, 여행 숙박 vs 손님 숙박, 새 예약 표현) + 경과조치 3개 | 개발 150 중 132 |
| g3.0 → g3.3 | V3 합본 반영(시행 구간 V3 12/1~, 개정 항목 11개 추가) | 개발 150 전부 · 봉인 41 / 37 (V2 / V3) |

## 경량화 수단을 고른 과정

세 질문으로 하나씩 지웠다. ① 우리 조건(A40 48GB 1장, 4일, vLLM)에서 실제로 작아지나 ② 판정·근거 정확도를 지키나 ③ 처음 보는 질문에도 통하나.

| 수단 | 판단 | 근거 |
| --- | --- | --- |
| 양자화 4비트 | 기본값 | 학습 없이 끝나는 유일한 수단. 같은 모델이면 4비트 ≥ 8비트, A40은 FP8 연산이 없어 8비트가 더 느림 |
| 작은 기성 모델 그대로 | 단독 탈락 → 학생으로 | qwen3-4b 85 vs 기준선 91(p2 + R3, 합격선 88). 1~2B는 반복 잘림 |
| 희소화(비구조적) | 탈락 | 0도 한 칸을 차지해 크기·속도가 그대로 |
| 2:4 반구조 희소화 | 탈락 | 품질 회복에 대규모 재학습 필요, A40 가속 미확인 |
| 층 제거 | 초안 후 중단 | 재학습 없이 빼면 산술·JSON이 먼저 무너짐. 회복 학습 비용 = 증류 |
| **시퀀스 증류** | **채택** | 교사 답으로 학습, 토크나이저가 달라도 됨. 4B 72 → 95 |
| 로짓 증류 | 탈락 | 교사(gemma)와 학생(qwen)의 어휘가 달라 확률을 짝지을 수 없음 |
| 추론 엔진(TensorRT-LLM) | 제외 | 크기·정확도는 그대로, 모델마다 엔진 재빌드. 최종 모델 확정 뒤 속도 후보 |
| 검색 + 판정 메모 | 채택 | qwen3-4b 29 → 49 |
| **판본 결정 코드 + 고정** | **채택** | 49 → 74. 단, 31B에게는 천장 |
| **후처리 R3** | **채택** | 기준선 79 → 91, 12B 91 → 98, 4B 74 → 85 |
| 후처리 R1 | 제외 | 모델이 뽑은 상한이 틀려 맞은 답을 망침 |
| 지시문 p2 → p3 | 채택 | 기준선 79 → 88, 12B 91 → 93 (4B는 74 → 67 하락. 지시문은 기준선 · 주력 모델 기준으로 골랐고, 학생은 교사와 같은 지시문으로 통일 → 증류로 보완) |
| JSON 출력 강제 | 채택 | 최종 후보 실행에서 형식 깨짐 0건 |
| 계산 코드 | 다음 1순위 | D109: 계산은 맞고 결론이 틀림 |
| 판정 규칙 사전 | 의도적 보류 | 위 '경계를 정한 기준' 참고 |
| 모델 라우팅 | 다음 | GPU 1장에 두 모델 부담, 나눌 기준 데이터 부족 |
