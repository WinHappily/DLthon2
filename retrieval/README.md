# dlthon2-rag : 개정되는 규약집에서 근거와 판본을 찾는 RAG 부품

해커톤 DLThon2(3인 팀, 2026.11.17 ~ 11.23)에서 **문서 · 검색 역할**로 만든 코드입니다.
60쪽짜리 공동생활 규약집(두 번 개정 : V1 → V2 → V3)에 대한 질문을 받아,

1. 질문을 정리하고 (잡담 · 이모지 · 전각 숫자)
2. 근거 쪽을 찾고 (BM25 + bge-m3 하이브리드, 조항 참조 따라가기)
3. **질문 속 날짜로 어느 판본을 적용할지 코드로 판정**하고
4. 판정 메모(금액 합산 · 판본별 수치 · 맞은 표 행)를 만들어

경량 LLM이 읽을 입력으로 넘깁니다. 모델 서빙 · 평가 · 발표는 다른 팀원이 맡았고, 이 저장소에는 없습니다.

> **규약집 본문과 평가 문항은 들어 있지 않습니다.** 규약집은 해커톤 운영진 배포 자료이고, 평가 문항과 정답지는 운영진과 팀원의 것이라 공개용 사본에서 뺐습니다. 아래 '빠진 것' 참고.

## 왜 판본을 코드로 정하나

규약집은 개정 합본입니다. V2 합본 한 권 안에 V1 수치(부칙 · 대조표)와 V2 수치(본문)가 같이 있어서, 판본별로 문서를 나눠 검색할 수 없습니다. 같은 질문도 사건 날짜에 따라 답이 뒤집힙니다.

| 질문 (같은 내용, 날짜만 다름) | 판본 | 생신 상한 | 24만 원이면 |
|---|---|---|---|
| 첫 결제 2026-11-21 | V2 | 22만 원 | 공동 처리 불가 |
| 첫 결제 2026-12-05 | V3 | 26만 원 | 가능 |

팀이 잰 결과(소형 모델 4개, 팀 개발 문항 150개) : 판본을 코드가 정해 주면 상태 + 판본 정답률이 **+4 ~ +23%p**, 판정 메모는 **+6 ~ +15%p** 올랐습니다. 실제 검색 결과는 정답 쪽을 넣어 준 경우와 −5 ~ +3%p 차이였습니다.

## 바로 해 보기 (규약집 없이도 됨)

판본 규칙은 설정 파일(`config/versions.json`)만으로 동작합니다.

```bash
pip install -r requirements.txt
python -m rag.version "시아버지 생신 식사 15만 원과 선물 9만 원, 첫 결제는 2026-12-05" --doc V3
python -m rag.version "시아버지 생신 식사 15만 원과 선물 9만 원, 첫 결제는 2026-12-05" --doc V2
python -m eval.eval_version                                   # 직접 만든 판본 문항 30개
python -m eval.eval_version --questions eval/questions_version_holdout.jsonl   # 처음 보는 15개
```

같은 질문이 V3 문서로는 V3, V2 문서로는 V2로 나옵니다(V2 문서는 V3 시행 구간을 모름).

## 규약집 PDF가 있을 때 (검색까지)

```bash
python -m rag.extract --doc V2 --pdf pdf/rulebook_V2.pdf      # 쪽 · 표 행 조각 → data/V2/
python -m rag.index --doc V2 --embed BAAI/bge-m3              # 벡터 색인 (GPU 권장, 코랩 노트북 참고)
python -m scripts.export_retrieval --questions <질문.jsonl> --name mine --doc V2
```

- 질문 파일 : jsonl(`{"id", "question"}`) 또는 csv(`문항번호`, `질문`)
- 결과 한 줄 = 질문 하나 : `hits`(근거 쪽 본문 · 들어온 이유), `version`(판본 판정), `brief_text`(판정 메모), `messages`
- 코랩 : `notebooks/role_A_colab.ipynb`
- 정확한 명령 인자는 각 파일 맨 위 설명을 보세요

## 구성

| 경로 | 하는 일 |
|---|---|
| `rag/extract.py` | PDF → 쪽 조각 · 표 행 조각(열 이름을 붙인 문장), 조항 · 표 번호 꼬리표 |
| `rag/search.py` | BM25 + bge-m3를 RRF로 합침, 조항 · 표 참조 한 단계 따라가기, 목차형 쪽은 참조를 따라가지 않음, 고정 쪽 |
| `rag/query.py` | 질문 정리 : NFKC · 이모지 · 'ㅋㅋ' 정리, 긴 잡담 글에서 사건 문장만 (모델에는 원문을 줌) |
| `rag/version.py` | **판본 규칙** : 개정 항목 찾기 → 날짜마다 역할(결제 · 예약 · 시작 · 고지 …) → 기준일 → 시행 구간. 경과조치(후속 결제 · 환불 · 전량 취소 후 새 주문), 경계 시각(24시 · 자정), 요일 조건, 조건부 예외 |
| `rag/brief.py` | 판정 메모 : 답 형식, 금액 합계, 판본별 수치, 맞은 표 행 |
| `rag/prompt.py` | 답변 프롬프트 틀 |
| `config/versions.json` | 판본 시행 구간, 문서별 설정, 개정 항목마다 키워드 · 예외 · 기준일 종류 |
| `scripts/add_version.py` | 새 판본 PDF에서 시행일 · 개정 항목 표를 찾아 설정에 추가 (초안, 사람이 확인) |
| `scripts/diff_versions.py` | 두 판본 사이 바뀐 쪽 · 항목 |
| `scripts/export_retrieval.py` | 질문 세트 → 검색 결과 파일 |
| `scripts/dump_query_emb.py` | 질문 벡터를 미리 저장 (torch가 없는 PC에서 같은 결과 재현) |
| `scripts/count_tokens.py` | 프롬프트 토큰 수 (chat template 적용 뒤) |
| `eval/eval_version.py` | 판본 규칙 채점 |
| `eval/eval_retrieval.py` · `eval_dense.py` · `eval_noise.py` | 근거 쪽 recall (BM25만 vs + bge-m3), 잡음 질문. 질문 · 정답 파일은 `--questions` · `--dev`로 직접 준다 |

### 판본 규칙 설정 예 (`config/versions.json` 의 `items`)

```json
{
  "name": "손님 숙박",
  "basis": "숙박 시작일",
  "all": [["손님", "친구", "선배"], ["숙박", "묵", "re:\\d\\s*박"]],
  "none": ["숙박비"],
  "none_soft": ["다과", "소모품", "세탁", "택시"],
  "decisive": ["re:합의\\S*\\s*(?:은|는|도)?\\s*(?:아직|없이|안|필요)"]
}
```

- `all` : 묶음마다 하나 이상, `any` : 하나만, `none` : 있으면 이 항목 아님
- `none_soft` : 비용만 묻는 질문은 판본과 무관하지만, `decisive`(판정 조건이 아직 열려 있음)가 있으면 이 항목
- `any_dated` : 날짜가 있을 때만, `weekdays` : 특정 요일에 시작한 사건만

## 만들면서 배운 것

- **자체 시험 점수는 세 번 다 높았다.** 직접 고르거나 보면서 고친 세트에서는 16/16 · 30/30 · 만점, 처음 보는 세트에서는 43/50 · 133/150 · 24개 놓침. 마지막 확인은 규칙을 고정하고 열어 보지 않은 봉인 세트로 했습니다.
- **개정 항목은 주제가 아니라 바뀐 수치로 잡는다.** 주제 낱말로 넓게 잡으면 판본과 상관없는 질문까지 날짜를 되묻습니다.
- **기본값은 조용히 뜻이 바뀐다.** "문서를 안 주면 가장 최근 문서"가 V3를 넣는 순간 V2 채점을 150 → 143으로 떨어뜨렸습니다.
- **목차형 쪽의 참조는 따라가지 않는다.** 참조가 수십 개인 색인 쪽이 참조 칸을 다 차지해 진짜 근거를 밀어냈습니다(근거 123 → 127/128).
